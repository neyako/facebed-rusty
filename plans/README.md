## How these map to the maintainer's focus + the deep pass

- **Security (deep pass)** → Plan 004. `ensure_absolute` trusts absolute inputs,
  and the `?type=3` shortcut + human redirect fetch/redirect to that host before
  normalization — so a crafted absolute-URL path leaks the Facebook account cookie
  to an arbitrary host (critical) and enables an open redirect. 004 enforces a
  Facebook-host allowlist at those sinks.
- **Crawl speed (focus)** → Plan 001 (algorithmic: kill the O(N²) partial-fetch
  scan) and Plan 005 (build: stop optimizing the release binary for size on a
  CPU-bound service).
- **Embed integrity (focus)** → Plan 002 (sticker images no longer leak in) plus
  the render/escape tests in Plan 006.
- **Cookie resilience (focus)** → Plan 003 (classify 429 vs checkpoint, cool down
  by cause instead of one flat 300 s, stop false "bad cookie" alerts).
- **Test coverage (deep pass)** → Plan 006 (first characterization tests for the
  extraction + embed path; first tests for `single_photo`/`photocom`/`stories`).

## Findings considered and not turned into plans

Recorded so they are not re-audited each run.

From the focused pass:

- **Full `Html::parse_document` on every fetch** (`src/fetch.rs:403`, perf):
  high-risk refactor touching every parser; raw-string fast paths already
  short-circuit the hot probe. Measure `parse_ms` (already logged) before
  attempting.
- **Reels/Watch re-walk every JSON block multiple times** (perf): the "search by
  key, never hardcode a path" design is deliberate (`AGENTS.md`); consolidation
  risks correctness on the most schema-fragile parsers for an uncertain win.
